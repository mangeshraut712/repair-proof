# Repair Proof Implementation Plan
**Goal:** Offline-testable review-first Meta repair application.
**Architecture:** Trusted fixture registry → bounded sanitation → replay or strict Meta proposal → independent policy → optional fail-closed isolated verification → review packet.
**Tech Stack:** Python FastAPI/Pydantic/httpx, standard unittest, HTML/CSS/JS.
**Spec:** docs/DESIGN.md
## Constraints
New authored files only. No live inference, publishing, credential creation or paid operations. No arbitrary paths/commands. No host execution of patch.
## Review focus
Malformed/oversized model responses; injection and secrets in logs; path/hash/AST policy bypasses; disabled sandbox and timeout failures; repeated UI interactions and stale verification state.
